# Архитектура

## Сборка
```
src/engine/*.js  ─┐  склейка по номеру → const SIM = (() => { … return {…} })();  → dist/sim.cjs
src/ui/*.js      ─┼─ склейка по номеру → { … }  (один блок <script>)
src/ui/atlas-data.json ─ готовый атлас 100 миров (посчитан на старой «материковой» модели)
src/index.template.html ─ разметка, стили, места /*SIM*/ /*UI*/ /*ATLAS*/[]  → dist/index.html
```
`tools/build.mjs` ничего не транспилирует: это простая склейка текста. Значит, все функции движка лежат в одной области видимости, порядок файлов важен только для `const`/`let` верхнего уровня, которые используются при загрузке (`SYL`, `N`, `CS`, таблицы). Публичный API — `return { … }` в конце `src/engine/63-yearly.js`:

```js
SIM.newWorld(seed, params) → S      // новый мир-остров
SIM.step(S)                         // один день (тик); 360 тиков = год
SIM.advanceMinutes(S, minutes)      // часы внутри дня, шаг на каждой полуночи
SIM.prepareDay(S) → { end, plans }  // прогноз из состояния начала дня, без изменений S
SIM.eventTime(event)               // минуты от начала мира
SIM.shock(S, kind)                  // вмешательство: мор, засуха, набег…
SIM.serialize(S) / SIM.restore(obj) // сохранение
SIM.date(S), SIM.key(a,b), SIM.gini(arr), SIM.regime(S,g), SIM.landTop(S), SIM.popOf(S), SIM.kin(S,a,b), SIM.kidsOf(S,a), SIM.groupName(S,g)
```

В Node аудит, атлас и проверка летописи распределяют острова по доступным ядрам и выводят результаты в порядке сидов. `SOCIETY_WORKERS=1` запускает последовательный прогон. Положительное целое число ограничивает число потоков.

## Время
`S.tick` — число завершённых суток, `S.minute` — минута открытого дня от 0 до 1439. `step` рассчитывает план дороги, встречи, работу и жизнь за день. `monthly` срабатывает раз в 30 тиков, `yearly` раз в 360. Лёд держится с 12-го по 77-й день года.

`prepareDay` считает один день из копии мира и возвращает планы взрослых по идентификаторам. В плане есть место занятия, маршрут, минуты выхода, прихода и возвращения. Для Ч2 после планирования доступно `a.commute`. Это минуты местной дороги туда и обратно, `null` при закрытом или слишком длинном пути и 0 без местной дороги. Координаты взрослого (`a.x/y`) в движке обозначают его место занятия или последнюю точку дальней дороги. Положение в минуту просмотра вычисляет `routinePosition`.

Web Worker возвращает планы и датированные события открытого дня и держит рассчитанный итог до полуночи. После загрузки план воспроизводится из сохранённых `tick`, `minute` и состояния начала дня. «Сцена», «Дни», «Годы» и «Века» меняют скорость продвижения этих часов. Быстрый просмотр может пересечь несколько полуночей за запрос. Видимые записи сортируются по времени и идентификатору, отметки на карте показываются один раз. Суточные итоги остаются в состоянии к следующей полуночи.

При слежении режиссёр останавливает готовую пачку в начале дня подходящего события. За два часа он включает «Дни», за полчаса — «Сцену». Влияние режиссёра ограничено часами просмотра и камерой. В тесте с явной меткой свадьбы сравнивается состояние мира при одинаковом времени с включённым и выключенным режиссёром.

Ч4 может передать `minute` в `log` или `note`. У события, рассчитанного шагом, `t` остаётся номером полуночи, когда вступают в силу его суточные итоги. Час внутри рассчитанного дня кодируется полем `minute`. `eventTime` переводит пару в абсолютные минуты. Запись без часа видна к полуночи. События в начальном состоянии относятся к дню 0. Ч3 использует этот формат для открытия событий по часам.

## Состояние `S` (главное)
- `S.rng` — генератор, единственный источник случайности. `S.tick` и `S.minute` — единые часы.
- `S.agents` — живые взрослые: `id name x y age life sex spouse mother father group role job energy wealth status skill rep trust patron bio drama …`.
- `S.kids` — дети до 15 лет (вне карты, едят из запасов деревни), растут в `growUp`.
- `S.groups` — деревни и кочевые общины: `members leader home(x,y) store(stock) gov faith take lord treasury well fboats goats pasture …`.
- `S.nodes` — ресурсы на земле: угодья, лес, рыба у берега (`kind:'fish'`), каменоломни.
- Карта: `S.ter` (50×50 клеток по 20 px: `s` море, `b` пляж, `w` река, `h` холм, `f` лес, `g` трава), `S.wood`, `S.ford`, `S.bridge`, `S.wear`/`S.road` (протоптанность → дороги), `S.frozen`, `S.springs`, `S.isle` (центр и радиус острова), `S.river`.
- Строительная площадка `g.site` хранит идентификатор, вид, координаты, габариты, поворот, этап и прогресс работ, зарезервированные материалы и объём доставленного. `a.siteTrip` отмечает путь строителя с заказа. У законченных объектов в состоянии остаётся их геометрия.
- Участки частокола `g.fortifications` хранят линии стен, проезды, высоту и число кольев. Отдельная площадка `palisade` содержит такой же план до сдачи. На каждую постройку заново указываются сроки и ресурсы. Кэш пересечения стен с клетками восстанавливается из геометрии.
- Война и политика: `S.wars`, `S.hostility`, `S.alliances`, `S.states`, `S.truce`.
- История: `S.events` (лента для людей, `{t,type,text,…}`), `S.legends` (архив судеб), `S.stats` (счётчики: births, childDeaths, death, sick, burnout=голод, war, plague, drown, lostAtSea, killed, coups, wars…).
