# AGENTS.md — правила для любого ИИ-агента (Claude, GPT, Gemini, Copilot…)

Прочитай этот файл целиком до первой правки. Потом `docs/ARCHITECTURE.md` (где что лежит) и `docs/ROADMAP.md` (что делать). Механики описаны в `docs/MECHANICS.md`.

## Что это
«Лаборатория обществ» — симуляция без игрока. Остров, лодки с первыми людьми в год 0, дальше всё само: деревни, вода, еда, ремёсла, браки, власть, войны, мор, судьбы отдельных людей. Пользователь только наблюдает и меняет вводные. Цель автора: **реалистичный автономный мир, в котором вырастают настоящие человеческие истории**. Сначала доводим до идеала один остров, потом архипелаг и атлас миров, потом красивый движок отрисовки.

Владелец — Кирилл. Язык интерфейса, событий, летописей и документации для него — **русский**. Код, имена переменных и коммиты — можно по-английски.

## Как работать
```bash
npm run build     # src/ → dist/index.html (вся страница одним файлом) и dist/sim.cjs (движок для Node)
npm test          # сборка + smoke: 3 острова × 40 лет, инварианты (никто не стоит в море, нет NaN, нет исключений, serialize/restore работает)
npm run audit     # демография и причины смертей на 6 островах × 80 лет — сверка с реальностью
python3 tools/page_check.py   # открыть страницу в headless-браузере, 40 лет, все вкладки, 3D, ошибки JS (нужен playwright)
```
Никаких зависимостей npm. Нужен только Node ≥ 18. Страница — один самодостаточный HTML; three.js r128 подгружается с CDN только для режима 3D.

**Порядок любой задачи:** прочитать нужные файлы → правка в `src/` → `npm test` → `npm run audit`, если трогал демографию, еду, войну, болезни → `page_check.py`, если трогал UI → обновить `docs/` (MECHANICS, ROADMAP, CHANGELOG) → коммит.

## Жёсткие правила
1. **Правь только `src/`.** `dist/` — результат сборки; пересобери и закоммить его вместе с исходником, чтобы `dist/index.html` всегда работал.
2. **Детерминизм.** Вся случайность в движке только через `S.rng()` (mulberry32 от seed). Никаких `Math.random()`, `Date.now()`, обращений к DOM внутри `src/engine/`. Один seed — один и тот же мир.
3. **Движок не знает про UI.** `src/engine/` — чистая логика, работает в Node. UI читает состояние `S` и вызывает `SIM.step(S)`.
4. **Механики — правила, не ИИ.** Никаких вызовов LLM внутри симуляции. Люди решают по простым правилам с весами и случайностью. LLM-рассказчик возможен позже только как надстройка, читающая летописи.
5. **Реализм проверяется числами.** Новая механика должна оставлять `npm run audit` в коридорах из `docs/MECHANICS.md` («Сверка с реальностью»). Если коридор сознательно сдвинут — объясни в CHANGELOG.
6. **Новые поля состояния** должны переживать `serialize/restore` (см. `src/engine/63-yearly.js`). Старые сохранения можно ломать, но тогда подними версию модели `MODEL` в `src/engine/00-core.js`.
   Любая правка механики, меняющая ход мира, — подними `MODEL.v` (m13 → m14), `MODEL.date` и `MODEL.note` в `src/engine/00-core.js`: версия видна в шапке страницы под названием, а атлас, посчитанный на старой версии, сбрасывается.
7. **Не сломай остров:** люди не появляются из краёв карты и не ходят по морю; реку переходят только по мосту, броду или льду.
8. **Тексты для людей** — короткие, живые, по-русски, с согласованием по роду («Изгнан/Изгнана»). Никаких технических терминов в событиях.
9. **Производительность:** 100 лет мира в Node — порядка 30 с. Если твоя правка замедлила `npm test` больше чем на 20 %, оптимизируй (кэш путей, компоненты связности, редкие проверки раз в месяц, а не каждый день).
10. Не коммить секреты и ключи API. Страница публичная, ключ в ней виден всем.

## Как устроен код (коротко)
- `src/engine/NN-name.js` — части тела одной функции-обёртки `const SIM = (() => { ... })()`. Сборка склеивает их **по номеру в имени**, все функции видят друг друга. Новый файл — просто положи `NN-name.js` с правильным номером.
- `src/ui/NN-name.js` — части одного блока `{ ... }` в странице, тоже склеиваются по порядку.
- `src/index.template.html` — разметка и стили; `/*SIM*/`, `/*UI*/`, `/*ATLAS*/[]` заменяются при сборке.
- Подробности и карта функций — `docs/ARCHITECTURE.md`.

## Ветки и запросы на слияние
- **Никогда не пиши прямо в `main`.** Одна задача — одна ветка (`task/1.1-adult-deaths`) и один pull request в `main`, открытый черновиком в начале работы. Автор (Кирилл) сам смотрит и нажимает Merge.
- В описании PR: что сделано, какие критерии приёмки выполнены, цифры `npm run audit` до и после, что не получилось.
- Перед PR: `npm test` проходит, `dist/` пересобран и закоммичен (CI это проверяет).
- После слияния мир сам публикуется на GitHub Pages: https://kirgoncharov-eng.github.io/society-simulator/

## Несколько агентов одновременно
Над проектом параллельно работают разные агенты (Claude, Codex/GPT и другие). Отметка «В работе» в ROADMAP лежит в твоей ветке и видна другим только после слияния, поэтому **задачу занимает открытый pull request**, а не отметка.
1. **Перед началом** посмотри открытые PR и ветки (`git fetch --prune`, `git branch -r`, список PR на GitHub). Если на задачу уже есть открытый PR — её не бери, даже если в ROADMAP она свободна. Если твоя задача пересекается по смыслу с чужим PR (те же механики, те же файлы) — не дублируй: спроси автора или строй поверх, когда тот PR сольют.
2. **Займи задачу сразу:** первым делом создай ветку от свежего `main`, закоммить в ROADMAP строку `В работе: <агент>, <дата>` и открой **черновой (draft) PR**. В названии — номер задачи из ROADMAP и суть: `Д2: личные связи с памятью`. В описании — кто ты (Claude, Codex…) и план.
3. **Новую задачу в ROADMAP не придумывай сам.** Предложи её автору; в ROADMAP её вписывает автор или агент по его прямому согласию.
4. **Перед тем как снять с PR пометку «черновик»** подтяни свежий `main` (`git fetch && git merge origin/main`), разреши конфликты, пересобери `dist/`, снова прогони `npm test` и, если трогал механику, `npm run audit`. Чужие строки в CHANGELOG, ROADMAP и MECHANICS не удаляй: конфликт в документах — это почти всегда «оставить обе записи».
5. **Версия модели** (`MODEL.v` в `src/engine/00-core.js`) — следующая после той, что сейчас в `main`. Если пока ты работал, в `main` слили ту же версию, при слиянии с `main` возьми следующий номер.
6. **Направления назначает автор.** Кто что сейчас ведёт, видно по открытым PR. Чужие ветки и PR не правь: заметил проблему — напиши автору.
7. В подписи коммита и в описании PR указывай, какой ты агент, — автору так проще понимать, кто что сделал.

## Как взять задачу
Открой `docs/ROADMAP.md`, возьми верхнюю задачу, на которую нет открытого PR (см. «Несколько агентов одновременно»), займи её черновым PR. Сделай ровно её, с критериями приёмки. В конце: отметь задачу сделанной, добавь строку в `docs/CHANGELOG.md` (дата, модель, что изменилось, цифры аудита до/после). Одна задача — одна ветка или один коммит с понятным сообщением.

Если задача неясна или противоречит этим правилам — не угадывай, оставь вопрос в `docs/QUESTIONS.md`.
